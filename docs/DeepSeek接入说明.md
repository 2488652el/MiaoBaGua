# DeepSeek 接入说明 · 1.1.6

## 主播流程

在控制台打开 DeepSeek 设置，粘贴自己的 API Key，保存并测试连接。模型默认使用 `deepseek-flash`，另可选 `deepseek-v4-pro`。采用非思考模式，直接流式显示回答。

填写粉丝问题 → 摇骰子 → 冻结本次问题和主题 → 骰子结束 → 自动发送本次问题、主题、本卦、变卦、动爻、体用与五行关系 → 显示结论及详细解读。

内容顺序为问题结论、卦象依据、体用与变化、行动建议。结果定位为传统文化的象征性解读，不把随机结果当成事实判断或确定预测。AI 回答仅在主播控制台显示。

## 明确结论要求（1.1.6）

- 第一段首句使用“按本次卦象，我的判断是：”，给出一个明确主判断；肯定表达不等于只给有利结论。
- 比较或二选一题直接点名更建议的选项，行动题明确做、不做或暂缓，开放题给首要方向。
- 禁止用“可能、也许、或许、看情况、因人而异、取决于你自己”代替主判断；有相反信号时说明主次与取舍，不将相反结论并列后交给观众自行选择。
- 本卦象意、体用五行方向、动爻位置及阴阳变化、变卦都必须联系本次具体问题，说明如何支持或限制结论。行动建议按优先级排列，与主结论一致。
- 缺少现实信息时明确缺失项并给核实动作，不编造现实事实、他人想法、成功概率或应验日期。医疗、法律、投资等问题不能仅凭卦象作高风险决定。

新提示词随每次请求发送，不依赖模型记忆。旧回答保留原文；手动“重新解读”会用同一记录的问题与卦象发送新请求。升级不自动重新生成。此更新未改变体用判定规则版本。

## 体用约定与提示词

本应用采用“动爻所在卦为体，另一个为用”。本卦初、二、三爻动时下卦为体；四、五、上爻动时上卦为体。上下卦相同也按位置区分。体用五行取本卦，变卦不重新指定体用。

系统提示词明确写入此规则和五行生克方向，要求模型在“体用与变化”段先解释动爻位置及体用归属。每次请求资料同时包含规则版本、规则说明、动爻所在卦、体用位置和已计算的五行关系。模型应沿用提供的数据。

新回答记录规则版本 `moving-trigram-is-body-v1`；没有此标记的旧回答保留原文、默认折叠，并标注“旧规则解读”。历史本地数据会重算，旧 AI 文本需用户点击“按新规则重新解读”才发送更新请求。

## 发送与保存

- 网络目的地固定为 DeepSeek 官方 `https://api.deepseek.com/chat/completions`。
- 测试连接调用 `/models`，只检查密钥和所选模型，不生成解读。
- 观众昵称、其他历史、账户路径不加入请求上下文。
- 密钥只在主进程使用，由 Electron `safeStorage` 系统加密后保存到用户数据目录的 `deepseek-settings.json`。加密不可用时仅本次运行使用，不明文落盘。
- 问题与回答保存到原有 `oracle-state.json` 的最近 30 条记录。密钥不会保存到这个文件，也不会通过广播状态返回渲染窗口。
- 输入密钥的密码框在保存后清空；留空保存表示保留已存密钥。设置内可以移除密钥。
- 直播窗口没有配置、测试连接、发起解读或取消解读的 IPC 权限。

## 连续问答和异常处理

- 问题在点击摇骰子时固定；之后编辑只影响下一次。
- 一次结果只自动请求一次。问题为空、没有密钥、关闭自动时不自动调用。
- 点击新一次摇骰子会停止前次生成。旧请求的迟到回复不会覆盖新记录。
- 请求超时为 90 秒，可手动重试。401、402、429、500、503 等状态有对应提示，不回显服务端原始错误正文。
- 中断、截断、拒绝或空结果不标记为成功；部分文字会保留并标注错误。
- 停止仅能终止本地请求；服务方已发生的 token 用量可能仍会计费。
- 应用重启会恢复已完成结果，中断结果显示可重试，不自动补发付费请求。

## 验证范围

单元测试使用注入的模拟网络传输，覆盖 384 种请求资料、SSE 中文碎片、错误、超时、取消、迟到回复、密钥保存及问题冻结。

真实 Electron 端到端测试使用独立临时数据目录，在测试进程内模拟官方接口，覆盖配置、连接测试、自动解读、重试、停止、历史恢复及直播隔离；不调用真实账户。首次真实 API Key 连接需要在应用内完成，真实模型回答质量需结合真实问题验收。
